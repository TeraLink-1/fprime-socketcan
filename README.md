## Using this library

This repository is an [F´ library](https://fprime.jpl.nasa.gov/latest/docs/how-to/develop/develop-fprime-libraries/)
providing `SocketCan.LinuxCanDriver`, a SocketCAN driver for Linux, and the `SocketCan.CanSend` /
`SocketCan.CanReceive` ports and `SocketCan.CanFrame` type. It requires F´ v4.3.0.

Add it to your project as a submodule, pinned to a release:

```bash
git submodule add <repo-url> lib/fprime-socketcan
git -C lib/fprime-socketcan checkout <tag>
```

Don't initialize its own `lib/fprime` submodule; your project supplies F´.

List it in your project's `settings.ini`, then regenerate with `fprime-util generate`:

```ini
[fprime]
framework_path: ./lib/fprime
library_locations: ./lib/fprime-socketcan
```

In your topology, declare an instance and connect it:

```fpp
instance can: SocketCan.LinuxCanDriver base id 0x10000
```

- `run` to a rate group, which publishes the driver's telemetry
- `canSend` from the component that transmits frames
- `canReceive` to the component that handles received frames. It is called on the driver's read
  task, so connect it to an async input port.

The interface's bitrate and restart settings come from the system configuration (for example
`ip link set can0 type can bitrate 500000 restart-ms 100 && ip link set can0 up`), not from the
driver. In your topology's startup and teardown code:

```cpp
can.open("can0");  // emits InterfaceOpenFailed or InterfaceDown on failure
can.start();
// ...
can.quitReadThread();
(void)can.join();
```

Because SocketCAN is a Linux-specific API, this library uses stub implementations on other platforms; code will compile but fail at runtime.

The library's unit tests are enabled by default. Turn them off with
`FPRIME_ENABLE_FPRIME_SOCKETCAN_UTS=OFF`; the option name comes from the directory the library is
cloned into.
